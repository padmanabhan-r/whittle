# Idea brainstorm

Forty candidate ideas for the neatHack entry, gathered and rated on 10 October
2026. Nothing here is decided.

What we are optimising for:

1. **Impact:** impressive, and useful enough that we and others keep using it.
2. **Uncrowded:** not what many of the 1,000+ registrants will also build.
3. **Stack:** neatlogs, Entire and cfo.ai doing real work while the agent runs.

Build time is deliberately ignored. We build with coding agents.

## How this list was made

Six models proposed ideas independently, from the same brief and without seeing
each other's answers:

Sethu's idea was added, overlapping ideas were merged into one entry (the
"From" column lists every model that proposed it), and one weak duplicate was
dropped. That left 40.

All six models then scored every idea from 1 to 10 on the three axes above. The
tables show the average of the six. Opus scored before seeing the others.
"Overall" is the plain average of the three axes.

These are model opinions, not measurements. The models rated each idea from a
two-sentence description, so a score says how the idea reads, not how well it
would work.

## Reading the results

- **Two ideas lead, and they are the same product seen from two sides.** The
  agent cost cutter (8.8) improves agents that run in production, using neatlogs
  traces as its input. The fleet auditor (8.6) improves the coding agents that
  write the code, using Entire sessions as its input. Together they are one
  pitch: an agent that audits your agents and proves it made them better.
- **The cost cutter is the only idea every rater scored 10 for stack use.** The
  trace shows the waste, the code graph finds the fix, and the saving becomes a
  scenario in the financial model.
- **The fleet auditor speaks to three of five judges.** Two are from Entire and
  one runs Orchestrator.inc, a tool for running fleets of coding agents. It
  depends on real Entire session data, which we do not have yet.
- **The self-healing trace fixer (rank 7) has high impact but is crowded.**
  It scored 8.7 for impact and 5.8 for uncrowded. Two models proposed it
  independently, and the raters expect other teams to build it too.
- **Three ideas outside the "improve agents" family rated well:** the
  outage-to-resilience agent (8.2), the technical due diligence agent (8.2) and
  the release captain (8.1). Due diligence is one of the few high-ranked ideas
  that uses cfo.ai as a working tool and not only as a business plan.
- **Sethu's CNC agent ranks 21st.** It is among the least crowded ideas (8.8)
  and scored well for impact (7.5), but lowest of the top 25 for stack use
  (5.2), because neatlogs and Entire help build it without being part of it.
- **The site's own examples score worst.** The GitHub issue fixer, research
  agent and prospect builder are the most crowded entries on the list.

### Suggested shortlist

1. **Agent cost cutter**, with the fleet auditor as its second half once Entire
   is installed and producing sessions.
2. **Regression bisector with session blame**, if we want the entry that leans
   hardest on Entire.
3. **Outage-to-resilience agent**, if we want something outside developer
   tooling for agents.

## The ideas in detail

In rank order.

### 1. Agent cost cutter

- **Domain:** Developer tool for AI agents
- **Field:** AI engineering, cost optimisation
- **What it does:** Point it at an agent's repo and its neatlogs project. It reads recent traces, finds waste (cache prefix that changes each call, repeated tool calls, oversized context, doomed retries, a model tier that is too big), patches the code, reruns and proves the saving with two traces, holding quality steady with an eval.
- **Sponsor stack:** neatlogs MCP is the input (search_traces, get_trace_context) and the proof; evals guard quality. entire graph search and impact find and safely change the call sites. Cost per run before and after becomes two cfo.ai scenarios showing the margin gained.
- **Scores:** impact 9.3, uncrowded 7.2, stack 10.0, overall 8.8
- **From:** Opus; Gemini (DynamicAgentPricer)

### 2. Fleet auditor for coding agents

- **Domain:** Developer tool for AI agents
- **Field:** AI-assisted software development, engineering management
- **What it does:** Audits a team's fleet of coding agents: reads their sessions, scores each for correctness, wasted tokens and policy violations, ranks agents, skills and tools, rewrites the weakest agent's prompt or skill, and re-benchmarks to prove the gain.
- **Sponsor stack:** Entire is the data source: tokens, experts, checkpoints and search link sessions to merged code. neatlogs evals judge sampled sessions, experiments test the rewritten prompt, detections encode policy (PII in prompts, cost ceilings). cfo.ai models savings per fleet with percentage-of-savings pricing.
- **Scores:** impact 8.3, uncrowded 7.8, stack 9.5, overall 8.6
- **From:** Kimi (Fleet Auditor)

### 3. Outage-to-resilience agent

- **Domain:** Operations and reliability tool
- **Field:** Site reliability engineering
- **What it does:** Turns a past incident into a tested reliability improvement: reconstructs the failure, implements the smallest fix, replays the failure as a permanent test, and proves recovery time and error rate improved.
- **Sponsor stack:** neatlogs is the incident evidence and the judge of the replay; detections catch tool loops and unverified claims. entire-graph finds callers, data flow and co-change around the fault; entire investigate and review check the fix. cfo.ai quantifies outage cost under three scenarios.
- **Scores:** impact 8.2, uncrowded 7.5, stack 9.0, overall 8.2
- **From:** GPT-5.6 Luna (Outage-to-Resilience Agent)

### 4. Technical due diligence agent

- **Domain:** Business analysis tool
- **Field:** Venture capital, mergers and acquisitions
- **What it does:** Turns a startup's data room (repos, metrics, deck) into a diligence report, checking every claim against a source and flagging contradictions.
- **Sponsor stack:** entire recap, experts and graph diff give the engineering reality (shipping cadence, bus factor). cfo.ai rebuilds and stress-tests the target's financial model. Crustdata checks company and team facts. neatlogs detections act as the fact-check gate.
- **Scores:** impact 8.2, uncrowded 7.8, stack 8.7, overall 8.2
- **From:** Gemini (AgenticTechnicalDueDiligence); Kimi (Deal Diligence Agent)

### 5. Regression bisector with session blame

- **Domain:** Developer tool for debugging
- **Field:** AI-assisted software development
- **What it does:** Given a failing test, bisects history to the commit that broke it, pulls the prompt and agent session behind that commit, explains what the coding agent misunderstood, fixes it, and writes the lesson to shared memory so it is not repeated.
- **Sponsor stack:** Entire is the core: checkpoints, entire why, blame and Brain. neatlogs traces each bisect step and test run as a long stateful run. cfo.ai prices per seat with cost per investigation.
- **Scores:** impact 7.7, uncrowded 7.7, stack 8.8, overall 8.1
- **From:** Opus

### 6. Release captain

- **Domain:** Operations and release tool
- **Field:** DevOps, release engineering
- **What it does:** Shepherds a release: builds the changelog from agent-session evidence so each entry links to the prompt that wrote the code, canary-deploys, watches live traces for regressions, and rolls back or patches automatically.
- **Sponsor stack:** entire recap, dispatch, checkpoints and why build the evidence-linked changelog. neatlogs canary comparison, thresholds and alerts are the deployment gate. cfo.ai models cost per release against DevOps headcount.
- **Scores:** impact 8.2, uncrowded 7.0, stack 9.0, overall 8.1
- **From:** Kimi (Release Captain)

### 7. Self-healing trace fixer

- **Domain:** Developer tool for AI agents
- **Field:** AI engineering, reliability
- **What it does:** Watches an agent's production traces, notices when a feature degrades, reads the failing trace and neatlogs' fix suggestion, finds the code, writes the fix, replays the same input and confirms the failure is gone before opening a pull request.
- **Sponsor stack:** neatlogs detections trigger it; triage_get and triage_get_investigation supply the root cause; a comparison trace is the proof. entire-graph locates code and entire why shows what the original session intended. cfo.ai prices per verified fix.
- **Scores:** impact 8.7, uncrowded 5.8, stack 9.5, overall 8.0
- **From:** Opus; Kimi (TraceFixer)

### 8. Pricing and unit-economics agent

## What each sponsor tool does

### Required: neatlogs (observability for agents)

| Feature | What it does |
|---|---|
| SDK | `neatlogs.init()` then `neatlogs.wrap(client)` traces every model call. `@neatlogs.span` and `neatlogs.trace()` group a run under one root. Python needs 3.10 to 3.13 |
| Traces | Span tree per run with inputs, outputs, latency, tokens and cost |
| Detections | Rules that flag traces: regex, numeric condition, PII, or a semantic classifier |
| Alerts | Notify when a detection fires or a metric crosses a threshold |
| Evals | Send traces to an AI judge or a human reviewer with a rubric |
| Experiments | Prompt version control and a sandbox to test prompt changes |
| Fixes | AI-written fix suggestions from failing traces, with a root-cause trail |
| Session replay | Play a run back step by step |
| MCP server | `https://ingest.neatlogs.com/mcp`, authenticated with the project key. Tools include `search_traces`, `get_trace_context`, `list_detections`, `triage_list`, `triage_get`, `log_trace` |

The MCP server uses a plain bearer key, so **our own agent can call it while it
runs**, not only our coding agent.

### Required: Entire (repository context for coding agents)

| Feature | What it does |
|---|---|
| Checkpoints | Saves the agent session (prompts, tool calls, files) and links it to the commit with an `Entire-Checkpoint` trailer |
| entire-graph | Local code graph, no network. `entire graph search`, `impact`, `neighbors`, `diff`. Entire claims up to 71% lower token spend |
| `entire why` / `entire blame` | Explains the commit, checkpoint, prompt and session behind a file or line |
| `entire search` | Semantic and keyword search over checkpoints, commits, sessions and code |
| `entire investigate` | Multi-agent investigation from a prompt, issue or pull request |
| `entire review` | Multi-agent review of a branch with one final verdict |
| `entire dispatch` / `entire recap` | Shareable markdown summary of recent agent work |
| `entire tokens` | Token usage across sessions and checkpoints |
| Brain | Shared memory of decisions and lessons across agents |
| `entire mcp` | Runs Entire as an MCP server over stdio |

Everything is a CLI or a stdio MCP server, so **our agent can shell out to it at
run time**. `entire dispatch` also gives us ready-made build-in-public posts.

### Required: cfo.ai (financial model and business plan)

| Feature | What it does |
|---|---|
| Ari | An AI CFO that builds and updates a financial model and answers what-if questions |
| Scenarios | Base, upside and downside cases kept separate from the main plan |

## Patterns for using the stack cleverly

- **Traces as input, not only output.** The agent reads neatlogs traces through
  the MCP server and acts on them.
- **The graph as a tool.** The agent calls `entire graph search` and `impact` to
  find code instead of reading whole files, and the saving shows up in neatlogs.
- **History as evidence.** `entire why` tells the agent which session and prompt
  produced a line of code.
- **Measured cost into the plan.** Cost per run from neatlogs becomes the unit
  cost in the cfo.ai model, so the business plan rests on real numbers.
- **Build-in-public for free.** `entire dispatch` output becomes the #neatHack
  posts.
